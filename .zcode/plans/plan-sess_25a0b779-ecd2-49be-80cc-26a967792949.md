## Problem

When the agent navigates to a page (e.g., "go to github.com"), the native WebContentsView should become visible so the user sees the live page. Currently, the user only sees the NewTab dashboard because the native view never gets revealed.

**Root cause:** The agent uses `cdpController.navigate()` which calls `Page.navigate` via the Chrome DevTools Protocol debugger. While the `tabManager` listens for `did-start-navigation` events to flip `isNewTab=false` and call `view.setVisible(true)`, this event may not fire reliably when using the CDP debugger protocol. There's no explicit bridge between the agent's CDP navigation and the tab manager's visibility logic.

**How BrowserOS does it:** BrowserOS is a Chromium fork — the user always sees the real browser viewport natively. The extension UI lives in a side panel. The agent controls the browser via CDP and the user sees results live in the native viewport. No visibility toggling is needed because the viewport is always visible.

## Solution

Add an explicit `revealActiveTab()` method to `TabManager` and call it from the `AgentOrchestrator` whenever the agent executes a navigate action. This ensures the native view is always made visible when the agent navigates, regardless of whether the `did-start-navigation` event fires.

### Files to modify:

1. **`src/main/tabManager.ts`** — Add a public `revealActiveTab()` method:
   ```ts
   revealActiveTab(): void {
     if (!this.activeTabId) return
     const entry = this.tabs.get(this.activeTabId)
     if (!entry) return
     if (entry.info.isNewTab) {
       entry.info.isNewTab = false
       entry.view.setVisible(true)
       this.layoutActiveTab()
       this.emitUpdate()
     }
   }
   ```

2. **`src/main/services/AgentOrchestrator.ts`** — In `executeStep()`, after the action is executed, if the action type is `navigate`, call `this.tabManager.revealActiveTab()`:
   ```ts
   // After cdpController.executeAction()
   if (action.type === 'navigate') {
     this.tabManager.revealActiveTab()
   }
   ```

3. **`src/main/services/CDPController.ts`** — In the `attach()` method, call `Page.enable` after attaching the debugger to ensure navigation events are properly emitted:
   ```ts
   attach(tabId: string, webContents: WebContents): void {
     this.attachedTabs.set(tabId, webContents)
     webContents.debugger.attach('1.3')
     webContents.debugger.sendCommand('Page.enable')
   }
   ```

### Why this works:
- The `revealActiveTab()` call is explicit — it doesn't depend on any event firing
- It runs in the main process, synchronous with the agent's execution flow
- The `Page.enable` call ensures CDP navigation events are properly emitted as a defense-in-depth measure
- The existing `did-start-navigation` handler remains as a fallback for non-agent navigations
